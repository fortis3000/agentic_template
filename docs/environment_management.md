# Environment Management & Configuration Guide

This document describes the environment setup, package management, runtime configuration, and container networks of the Standardized Agentic Project Template.

---

## 1. Backend Environment (Python & uv)

The backend agent system runs on **Python 3.13** (or later) and uses the **Astral `uv`** package manager for fast, reproducible dependency resolution.

### Package Management with `uv`
- **Configuration (`pyproject.toml`)**: Lists core dependencies (such as `pydantic-ai`, `google-genai`, `fastapi`) and optional groups (`lint`, `test`, `dev`).
- **Synchronizing Dependencies**:
  To sync all package dependencies (including dev and linting tools) into a local `.venv` environment, execute:
  
```bash
  uv sync --extra all
  ```
  
- **Adding Packages**:
To add or update a python package, modify `pyproject.toml` and run `uv lock` / `uv sync`.

### Configuration Variables (`.env`)
Secrets and local runtime settings are loaded from the root `.env` file into python using `python-dotenv`.
> [!WARNING]
> Never commit the `.env` file to git. Use `.env.example` to document keys.

Common configuration keys:
- `GEMINI_API_KEY`: API key for Google Gemini model calls.
- `OPENAI_API_KEY`: Fallback key if using OpenAI models.
- `PHOENIX_API_KEY`: Telemetry token if using Arize Phoenix cloud dashboard.
- `OLLAMA_BASE_URL`: Endpoint address for local Qwen/Llama execution (default: `http://localhost:11434/v1`).

## 2. Frontend Environment (Node.js & npm)

The frontend dashboard runs on **Node.js 22+** (Alpine or Slim) and uses **npm** to handle packages.

### Package & Build Management
- **Configuration (`package.json`)**: Contains npm dependencies (like `svelte`, `@lucide/svelte`, `marked`) and development tools (like `typescript`, `vite`, `svelte-check`, `prettier`).
- **Installing Dependencies**:
  To resolve node dependencies locally, navigate to the frontend directory and run:
  
```bash
  cd frontend
  npm install
  ```
  
- **Linting & Code Style**:
The frontend enforces checks using `oxlint` (extremely fast linter) and `prettier` (styling checks):
  
```bash
  npm run lint         # Check linting errors
  npm run format:check # Validate code formatting
  npm run format:write # Apply Prettier formatting
  ```
  
- **Type Checking**:
  Strict TypeScript type verification is executed using:

```bash
npx --prefix frontend tsc -b frontend/tsconfig.json
```

## 3. Docker Compose Environment

For local sandboxing and multi-container orchestration, the project uses **Docker Compose** (`docker-compose.yml`) which spans three main services:

| Service | Port | Container Image | Directory Mount | Role |
| :--- | :--- | :--- | :--- | :--- |
| `agent-api` | `8000:8000` | `agentic-template:latest` | `.:/app` | Runs FastAPI backend and uvicorn server. |
| `agent-ui` | `5173:5173` | `node:22-alpine` (Vite) | `./frontend:/app` | Vite hot-reloading development UI server. |
| `phoenix` | `6060:6006` | `arizephoenix/phoenix` | None (Ephemeral) | OpenTelemetry span trace visualizer. |

### Container Networking
- The containers communicate internally over the default bridge network using docker service names (e.g. `http://agent-api:8000` or `http://phoenix:4317`).
- The Svelte application code runs directly inside the end-user's browser. Therefore, all fetch requests to the API backend must use the host-exposed address `http://localhost:8000`.

### Shared Volumes & State
- **Workspace Mounting**: Both `agent-api` and the root folder share the project workspace, meaning files generated by the agents in `data/` are immediately visible on the host filesystem and in the frontend File Browser.
- **Session History Persistence**: Message logs are stored in `data/sessions/`. This directory is mounted inside the container, ensuring conversation histories persist across restarts.
